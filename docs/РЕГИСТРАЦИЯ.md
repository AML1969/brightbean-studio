# Регистрация developer-кабинетов под BrightBean Studio

Везде ниже `{APP_URL}` — публичный https-адрес вашего инстанса, например `https://studio.example.com`, без слэша в конце. Все redirect URI должны совпадать с ним посимвольно, включая завершающий `/`.

Порядок: сначала раздел 0 (страницы на домене и токены), затем Meta → TikTok → Google → Telegram. Каждый кабинет независим, можно делать параллельно. После каждого раздела запишите дату в трекер в `docs/ЗАПУСК.md`.

Правило безопасности: все App ID/Secret, Client Key/Secret и токены хранить только в менеджере паролей и в `.env` на сервере. Не вставлять их в чат, в коммиты и в документы.

## 0. Подготовка (30 минут)

1. На домене опубликовать три статические страницы (достаточно простого HTML, раздаваемого тем же Caddy или GitHub Pages):
   - `{APP_URL}/privacy/` — политика конфиденциальности: какие данные берём из соцсетей (токены доступа, список страниц, метрики, комментарии), где храним (ваш сервер), как удалить (отключить аккаунт в приложении или написать на email).
   - `{APP_URL}/terms/` — условия использования.
   - `{APP_URL}/data-deletion/` — инструкция по удалению данных (Meta требует отдельный URL: «отключите аккаунт в Studio или напишите на …, данные удаляются в течение N дней»).
   Meta и TikTok требуют эти URL уже при настройке приложения, Google — при верификации.
2. Сгенерировать токены для вебхуков (любая случайная строка):
   `python3 -c "import secrets;print(secrets.token_urlsafe(32))"` — отдельно для `FACEBOOK_WEBHOOK_VERIFY_TOKEN` и `YOUTUBE_WEBHOOK_SECRET`. Записать в менеджер паролей.
3. Убедиться, что `{APP_URL}` уже открывается по https (этап 6 плана) или хотя бы отвечает заглушкой: Meta проверяет вебхук-URL в момент сохранения.

## 1. Meta: Facebook-страница, Instagram, приложение

### 1.1 Аккаунты и страница (20 минут)
1. Личный аккаунт Facebook (для кабинета разработчика нужен именно личный профиль с подтверждённым телефоном или email). Если его нет — создать и подтвердить.
2. Создать **Facebook-страницу** (Pages → Create): категория по вашей тематике. Страница — это то, куда публикует Studio; личный профиль публиковать нельзя.
3. Создать **Instagram-аккаунт** в приложении Instagram, затем Settings → Account type and tools → Switch to professional account → **Business**. Личные аккаунты API не поддерживают.
4. Связать Instagram со страницей: в настройках Facebook-страницы → Linked accounts → Instagram → Connect account. После этого Studio увидит Instagram через Facebook Login, это путь с максимальным набором функций (публикация, комментарии, DM, аналитика).

### 1.2 Кабинет разработчика и приложение (40 минут)
1. https://developers.facebook.com → Get Started → подтвердить телефон/email, принять условия, выбрать роль «Developer».
2. My Apps → **Create App**. Тип (use case) выбирать **Business** / «Other → Business». Имя приложения — название вашего бренда (его увидят при OAuth), контактный email — ваш.
3. **App settings → Basic**:
   - скопировать **App ID** и **App Secret** (Show) → менеджер паролей → `.env`: `PLATFORM_FACEBOOK_APP_ID`, `PLATFORM_FACEBOOK_APP_SECRET`;
   - **App domains**: домен из `{APP_URL}` без схемы;
   - **Privacy Policy URL**: `{APP_URL}/privacy/`; **Terms of Service URL**: `{APP_URL}/terms/`; **User data deletion** → Data deletion instructions URL: `{APP_URL}/data-deletion/`;
   - Category: Business and pages; загрузить иконку 1024×1024;
   - Save changes.
4. **Use cases** (слева) → Add use case → добавить четыре и в каждом открыть **Permissions and features** → Add для перечисленных разрешений:
   - **Manage everything on your Page**: авто `business_management`, `pages_show_list`, `public_profile`; добавить `pages_manage_posts`, `pages_manage_engagement`, `pages_read_engagement`, `pages_read_user_content`, `pages_manage_metadata`, `read_insights`.
   - **Messenger from Meta**: добавить `pages_messaging` (нужно для DM-inbox Facebook).
   - **Manage messaging & content on Instagram**: `instagram_basic`, `instagram_content_publish`, `instagram_manage_comments`, `instagram_manage_insights`, `instagram_manage_messages`, `pages_manage_metadata`.
   - **Access the Threads API** — только если нужен Threads; у него отдельные Threads App ID/Secret и отдельный redirect `{APP_URL}/social-accounts/callback/threads/`. Можно пропустить.
   Если Meta не даёт добавить `instagram_manage_messages`, в `.env` поставить `PLATFORM_INSTAGRAM_FACEBOOK_DM_SCOPES_ENABLED=false`, иначе авторизация упадёт на недоступном scope.
5. **Facebook Login for Business → Settings → Valid OAuth Redirect URIs**:
   ```
   {APP_URL}/social-accounts/callback/facebook/
   {APP_URL}/social-accounts/callback/instagram/
   ```
   Там же включить Client OAuth login и Web OAuth login. Save.
6. **Webhooks** (слева; либо Use cases → Manage everything on your Page → Webhooks) → объект **Page** → Subscribe to this object:
   - Callback URL: `{APP_URL}/webhooks/facebook/`
   - Verify token: значение `FACEBOOK_WEBHOOK_VERIFY_TOKEN` из `.env` (переменная должна быть уже на сервере и сервис перезапущен, иначе проверка не пройдёт)
   - после Verify and save подписать поля **feed**, **mention**, **messages**.
   Без этого комментарии приходят только 5-минутным опросом, упоминания — вовсе нет.
7. **App roles → Roles**: добавить администраторами/тестерами всех, кто будет подключать аккаунты в Studio до прохождения App Review (в режиме Development приложение работает только для ролей).
8. Режим приложения оставить **Development**. Этого достаточно для ваших страниц и Instagram, бессрочно.

### 1.3 Проверки Meta (запустить сразу, ждать 1–4 недели)
1. **Business Verification**: Business settings (business.facebook.com) → Security Center → Start verification. Нужны название и адрес организации, документ (для ИП/юрлица — регистрационный, для физлица Meta может потребовать Business Portfolio на физлицо), телефон. Без этого нельзя получить Advanced Access для чужих аккаунтов; для своих страниц не требуется.
2. **App Review** (после того как всё работает на своих страницах): App Review → Permissions and features → Request advanced access для `pages_manage_posts`, `pages_read_engagement`, `pages_manage_engagement`, `pages_read_user_content`, `instagram_basic`, `instagram_content_publish`, `instagram_manage_comments`, `instagram_manage_insights`, `read_insights`; при необходимости inbox — `pages_messaging`, `instagram_manage_messages`. На каждое разрешение: англоязычное описание сценария и запись экрана «вход → выбор страницы → публикация из Studio → результат на Facebook/Instagram». Запись делать на боевом домене. Ревью идёт итерациями, закладывать 2–3 раунда.

## 2. TikTok: кабинет и приложение (40 минут)

1. Аккаунт TikTok (обычный пользовательский, можно создать заново; это будет и тестовый аккаунт для Sandbox). Подтверждённый email.
2. https://developers.tiktok.com → Log in через TikTok → Register as developer: имя, email, согласие с условиями, подтверждение по email.
3. Manage apps → **Connect an app** → Create:
   - App name: ваш бренд; App icon (квадрат); Category: Content & Publishing / Social; Description на английском — 2–3 предложения о том, что приложение планирует и публикует контент владельца;
   - Terms of Service URL: `{APP_URL}/terms/`; Privacy Policy URL: `{APP_URL}/privacy/`;
   - Platforms → **Web** → Website URL: `{APP_URL}`.
4. **Add products**: **Login Kit** и **Content Posting API**.
   - Login Kit → Redirect URI:
     ```
     {APP_URL}/social-accounts/callback/social1/
     ```
     Именно `social1`: TikTok отклоняет URI со словом «tiktok», Studio принимает этот алиас.
   - Content Posting API → включить **Direct Post** (публикация сразу в профиль), не только Upload to inbox.
5. **Scopes** (вкладка приложения): `user.info.basic`, `video.publish`, `video.upload`, `video.list`.
6. Скопировать **Client Key** и **Client Secret** → менеджер паролей → `.env`: `PLATFORM_TIKTOK_CLIENT_KEY`, `PLATFORM_TIKTOK_CLIENT_SECRET`.
7. **Sandbox**: вкладка Sandbox → Create sandbox → добавить свой TikTok-аккаунт в Target users. У Sandbox **своя пара Client Key/Secret** — для тестов в `.env` ставить именно её, после аудита заменить на production-пару и переподключить аккаунт в Studio. До аудита видео публикуются только с приватностью «Only you»; композер Studio сам предлагает только доступные варианты.
8. **Аудит** (когда Sandbox-публикация работает): Submit for review. Нужны: демо-видео по каждому scope (логин через Studio, загрузка и публикация видео, просмотр списка), описание на английском, рабочие URL политики и условий. Срок от нескольких дней до нескольких недель.

## 3. Google: проект для YouTube (30 минут)

1. https://console.cloud.google.com → New project, имя — ваш бренд.
2. APIs & Services → Library → включить **YouTube Data API v3** и **YouTube Analytics API** (Google Business Profile API — только если нужен Google Business).
3. APIs & Services → **OAuth consent screen**: User type **External**; App name, Support email, Developer contact; App domain → Home page `{APP_URL}`, Privacy policy `{APP_URL}/privacy/`, Terms `{APP_URL}/terms/`; Authorized domains — ваш домен. Scopes можно не добавлять вручную, Studio запросит сами: `youtube.upload`, `youtube.readonly`, `youtube.force-ssl`, `yt-analytics.readonly`. **Test users** → добавить Google-аккаунт владельца канала. Publishing status оставить **Testing**.
4. APIs & Services → **Credentials** → Create credentials → OAuth client ID → **Web application**:
   - Authorized JavaScript origins: `{APP_URL}`;
   - Authorized redirect URIs:
     ```
     {APP_URL}/social-accounts/callback/youtube/
     ```
     (плюс `{APP_URL}/social-accounts/callback/google_business/`, если нужен Google Business).
   - скопировать **Client ID** и **Client secret** → `.env`: `PLATFORM_GOOGLE_CLIENT_ID`, `PLATFORM_GOOGLE_CLIENT_SECRET`.
5. Ограничения Testing-режима: refresh-токены тест-пользователей живут 7 дней (канал придётся переподключать еженедельно), видео, загруженные неверифицированным проектом, уходят private. Квота 10 000 юнитов в сутки, одна загрузка видео 1600; остаток показывает `manage.py quota_status`.
6. **Верификация** (обязательна, иначе 7-дневные токены навсегда): OAuth consent screen → Publish app → Prepare for verification. Нужны: подтверждение владения доменом в Search Console, политика конфиденциальности с описанием использования данных YouTube, видео демонстрации scope `youtube.upload` (чувствительный scope). Срок обычно 1–3 недели.

## 4. Telegram: бот и канал (10 минут, нужен к этапу 5 плана)

1. В Telegram открыть @BotFather → `/newbot` → имя и username бота → скопировать **токен** в менеджер паролей. Токен вводится в Studio при подключении канала (после реализации провайдера), в `.env` ничего не нужно.
2. Создать тестовый канал → Администраторы → добавить бота с правом **Post messages** (для групп — право отправки сообщений).
3. Для публичного канала запомнить `@username`, для приватного — chat_id (его покажет бот после добавления, либо пересылка сообщения из канала боту @userinfobot).

## 5. Что заполнить в `.env` по итогам

```
PLATFORM_FACEBOOK_APP_ID=
PLATFORM_FACEBOOK_APP_SECRET=
PLATFORM_INSTAGRAM_FACEBOOK_DM_SCOPES_ENABLED=true   # false, если Meta не дала instagram_manage_messages
FACEBOOK_WEBHOOK_VERIFY_TOKEN=
PLATFORM_TIKTOK_CLIENT_KEY=        # пара Sandbox до аудита, production после
PLATFORM_TIKTOK_CLIENT_SECRET=
PLATFORM_GOOGLE_CLIENT_ID=
PLATFORM_GOOGLE_CLIENT_SECRET=
YOUTUBE_WEBHOOK_SECRET=
```
После изменения `.env`: `docker compose restart app worker`. Страница Connect в Studio показывает платформу только когда обе переменные пары заполнены.

## 6. Проверка после регистрации

| Сеть | Как проверить | Ожидаемый результат |
|---|---|---|
| Facebook | Connect → Facebook → выбрать страницу | Аккаунт CONNECTED, `missing_scopes` пуст на карточке |
| Instagram | Connect → Instagram (via Facebook) | Аккаунт CONNECTED; пост с фото уходит (медиа должно быть доступно по `{APP_URL}/media/...`) |
| YouTube | Connect → YouTube под тест-пользователем | Загрузка короткого видео, статус Private |
| TikTok | Connect → TikTok (Sandbox-ключи) | Видео с «Only you», статус подтверждается до 30 минут |
| Вебхук Meta | Комментарий к посту на странице | Появляется в Inbox за секунды, а не через 5 минут |
