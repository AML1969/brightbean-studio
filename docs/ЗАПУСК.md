# Запуск BrightBean Studio у себя

Проект: Django 5.1 + PostgreSQL 16 + фоновый воркер (django-background-tasks) + HTMX/Tailwind.
Оригинал: https://github.com/brightbeanxyz/brightbean-studio (лицензия AGPL-3.0, см. раздел «Лицензия»).

Ниже три способа. Вариант A проверен на Windows 11 + Docker Desktop, вариант B на Linux (миграции, 2736 тестов, вход в UI).

## A. Docker Compose (самый простой для ежедневной работы)

Требуется Docker Desktop (Windows/macOS) или docker + compose plugin (Linux).

```bash
git clone https://github.com/AML1969/brightbean-studio.git
cd brightbean-studio
cp .env.example .env
# В .env поменять SECRET_KEY и ENCRYPTION_KEY_SALT на случайные строки.
# DATABASE_URL менять не нужно: docker-compose.override.yml сам подставляет
# адрес сервиса postgres (пароль берётся из POSTGRES_PASSWORD, по умолчанию postgres).
# Production на VPS: см. docs/ДЕПЛОЙ.md.
docker compose up -d --build
docker compose exec app python manage.py createsuperuser   # спросит только email и пароль
```

Открыть http://localhost:8000. Миграции выполняет сервис `migrate`, Tailwind
собирает сервис `tailwind` (первый запуск 1–2 минуты, следить: `docker compose logs -f tailwind`).
Воркер (`worker`) публикует посты по расписанию; без него посты зависают в очереди.

Остановить: `docker compose down`. Данные БД и загруженные файлы живут в volumes
`postgres_data` и `media_data` и переживают перезапуск.

### Windows (PowerShell) — проверено 27.10.2026

Перед клонированием один раз: `git config --global core.autocrlf false`.
Секреты без Python и без BOM-маркера (Windows PowerShell 5.1 добавляет BOM при `Set-Content -Encoding utf8`, django-environ тогда пишет `Invalid line`):
```powershell
Copy-Item .env.example .env
$gen = { -join ((48..57)+(65..90)+(97..122) | Get-Random -Count $args[0] | ForEach-Object {[char]$_}) }
$sk = & $gen 50; $salt = & $gen 40
$lines = (Get-Content .env) -replace '^SECRET_KEY=.*', "SECRET_KEY=$sk" -replace '^ENCRYPTION_KEY_SALT=.*', "ENCRYPTION_KEY_SALT=$salt"
[IO.File]::WriteAllLines("$PWD\.env", $lines)
```
Если на компьютере уже установлен PostgreSQL, порт 5432 занят: добавьте в `.env` строку `POSTGRES_HOST_PORT=5433` (контейнер базы публикуется только на 127.0.0.1).
Проверка задач воркера из PowerShell:
```powershell
docker compose exec app python manage.py shell -c "from background_task.models import Task; print(sorted(Task.objects.values_list('verbose_name', flat=True)))"
```

## B. Нативно с PostgreSQL (проверено)

Нужны: Python 3.12+ (проверено на 3.13), Node.js 20+, PostgreSQL 16, ffmpeg (для видео).

```bash
git clone https://github.com/AML1969/brightbean-studio.git
cd brightbean-studio

# 1. База
createdb -U postgres brightbean          # или psql -c "CREATE DATABASE brightbean;"

# 2. Конфиг
cp .env.example .env
# В .env задать:
#   SECRET_KEY=<случайная строка 50+ символов>
#   ENCRYPTION_KEY_SALT=<случайная строка>
#   DATABASE_URL=postgres://postgres:postgres@localhost:5432/brightbean
#   MEDIA_ROOT=<абсолютный путь к папке для загрузок, например ./media>
# Генерация секретов: python3 -c "import secrets;print(secrets.token_urlsafe(48))"

# 3. Python
python3 -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# 4. Tailwind (одноразовая сборка; для разработки UI — npm run start в отдельном окне)
cd theme/static_src && npm ci && npm run build && cd ../..

# 5. Схема БД и админ
python manage.py migrate
python manage.py createsuperuser          # только email + пароль, флага --username нет

# 6. Запуск (две вкладки терминала)
python manage.py runserver                # http://127.0.0.1:8000
python manage.py run_studio_worker        # публикация, аналитика, inbox
```

После первого входа приложение попросит принять Terms of Service, затем откроет
рабочее пространство «My Workspace» с календарём публикаций.

## C. Нативно на SQLite (без PostgreSQL, только для пробы)

Как вариант B, но в `.env`: `DATABASE_URL=sqlite:///db.sqlite3` и шаг с `createdb` пропустить.
Тесты на SQLite не рассчитаны, для них всё равно нужен PostgreSQL.

## Проверки качества

```bash
source .venv/bin/activate
export DJANGO_SETTINGS_MODULE=config.settings.test
export SECRET_KEY=test-secret-key-not-for-production
export DATABASE_URL=postgres://postgres:postgres@localhost:5432/brightbean_test
pytest -q                 # ~2 минуты, 2736 тестов; базу brightbean_test создаст сам
ruff check . && ruff format --check .
mypy apps/ config/ providers/ tests/ --ignore-missing-imports
python manage.py makemigrations --check --dry-run
```

## Что НЕ заработает на localhost

Подключение реальных соцсетей требует публичного HTTPS-адреса для OAuth-callback
`{APP_URL}/social-accounts/callback/{platform}/` и созданных developer-приложений
(Meta, TikTok, Google, LinkedIn, Pinterest). Для локальной проверки OAuth нужен
туннель (cloudflared/ngrok) и `APP_URL`/`CSRF_TRUSTED_ORIGINS` в `.env`, указывающие на него.
Без ключей Bluesky и Mastodon подключаются проще всего (логин/пароль приложения и
инстанс соответственно), это хорошие кандидаты для первого реального теста публикации.

## Лицензия

Оригинал распространяется под AGPL-3.0. Для личного/внутреннего использования
ограничений нет. Если изменённая версия будет доступна пользователям по сети
(SaaS, клиентский портал для заказчиков), AGPL обязывает предоставлять им
исходный код изменённой версии.

## Тесты и проверки внутри Docker

```bash
docker compose exec -e DJANGO_SETTINGS_MODULE=config.settings.test -e DB_HOST=postgres app pytest -q
docker compose exec app make check
```
Внутри контейнера хост базы для тестов нужно задать явно (`DB_HOST=postgres`), по умолчанию тесты ищут PostgreSQL на localhost.

## Проверка, что воркер работает

После `migrate` в админке `/admin/background_task/task/` должны быть повторяющиеся задачи
`run_publish_cycle`, `confirm_pending_publishes`, `run_inbox_sync_cycle`, `sync_all_account_analytics`.
Если их нет, миграции не выполнялись и воркер ничего не делает: посты останутся в статусе scheduled.
