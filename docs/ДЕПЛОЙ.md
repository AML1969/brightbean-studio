# Деплой на VPS (Docker Compose + Caddy)

Проверено: конфигурация `docker-compose.yml` + `docker-compose.prod.yml` публикует наружу только порты 80 и 443. Postgres и gunicorn доступны только внутри compose-сети, Redis включён, Caddy получает домен из `.env` и сам выпускает TLS-сертификат.

Нужно заранее: VPS (Ubuntu 22.04/24.04, 2 vCPU, 4 ГБ RAM, 40+ ГБ диска под видео), домен с A-записью на IP VPS, SSH-доступ с правами sudo.

## 1. Сервер (10 минут)

```bash
# Docker + compose plugin
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER && newgrp docker
docker compose version          # нужен v2.20+

# Файрвол: только SSH, HTTP, HTTPS
sudo apt-get install -y ufw
sudo ufw default deny incoming && sudo ufw default allow outgoing
sudo ufw allow OpenSSH && sudo ufw allow 80/tcp && sudo ufw allow 443/tcp
sudo ufw enable
```

Docker пробрасывает опубликованные порты в обход ufw, поэтому важно, что compose-файлы не публикуют 5432 и 8000. Проверка после запуска — ниже.

## 2. Код и `.env` (10 минут)

```bash
sudo mkdir -p /opt/brightbean-studio && sudo chown $USER /opt/brightbean-studio
git clone https://github.com/AML1969/brightbean-studio.git /opt/brightbean-studio
cd /opt/brightbean-studio
cp .env.example .env
chmod 600 .env
```

Сгенерировать три секрета (каждую команду отдельно, значения разные):
```bash
python3 -c "import secrets;print(secrets.token_urlsafe(48))"   # SECRET_KEY
python3 -c "import secrets;print(secrets.token_urlsafe(32))"   # ENCRYPTION_KEY_SALT
python3 -c "import secrets;print(secrets.token_urlsafe(24))"   # POSTGRES_PASSWORD (без спецсимволов, удобно для URL)
```

Отредактировать `.env` (`nano .env`), обязательные значения для production:
```
SECRET_KEY=<секрет 1>
ENCRYPTION_KEY_SALT=<секрет 2>          # после первого подключённого аккаунта не менять никогда
DEBUG=false                              # иначе отключается rate limiting
ALLOWED_HOSTS=studio.example.com
APP_URL=https://studio.example.com
APP_DOMAIN=studio.example.com
SIGNUP_MODE=invite

POSTGRES_PASSWORD=<секрет 3>
DATABASE_URL=postgres://postgres:<секрет 3>@postgres:5432/brightbean
REDIS_URL=redis://redis:6379/0

STORAGE_BACKEND=local
MEDIA_ROOT=/app/media
SERVE_MEDIA=true
CADDY_MEDIA_ROOT=/app/media

EMAIL_BACKEND_TYPE=smtp
EMAIL_HOST=<smtp.провайдера>
EMAIL_PORT=587
EMAIL_HOST_USER=<логин>
EMAIL_HOST_PASSWORD=<пароль>
EMAIL_USE_TLS=true
DEFAULT_FROM_EMAIL=studio@example.com
```
Замените `studio.example.com` на ваш домен везде. Платформенные ключи (`PLATFORM_*`) добавляются позже по `docs/РЕГИСТРАЦИЯ.md`.

## 3. Запуск (5–10 минут: сборка образа)

```bash
cd /opt/brightbean-studio
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build
docker compose -f docker-compose.yml -f docker-compose.prod.yml ps
docker compose -f docker-compose.yml -f docker-compose.prod.yml logs -f --tail=50 migrate app caddy
```
Ожидаемо: `migrate` завершился с кодом 0, `app`, `worker`, `postgres`, `redis`, `caddy` в состоянии running, в логе Caddy строка о выпущенном сертификате.

Создать администратора:
```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml exec app python manage.py createsuperuser
```

Чтобы не печатать два `-f` каждый раз:
```bash
echo 'COMPOSE_FILE=docker-compose.yml:docker-compose.prod.yml' >> .env
```
после этого достаточно `docker compose ps`, `docker compose logs -f worker` и т. д.

## 4. Проверки

| Проверка | Команда | Ожидание |
|---|---|---|
| Сайт по https | открыть `https://ваш-домен/` | форма логина, замок в браузере |
| Health | `curl -s https://ваш-домен/health/` | `{"status": "ok"}` или аналог, код 200 |
| Открытые порты снаружи | с другой машины `nmap -p 22,80,443,5432,8000 ваш-домен` | 22/80/443 open, 5432 и 8000 closed/filtered |
| Задачи воркера | `https://ваш-домен/admin/background_task/task/` | есть `run_publish_cycle`, `confirm_pending_publishes`, `run_inbox_sync_cycle`, `sync_all_account_analytics` |
| Rate limiting включён | `docker compose exec app python -c "from django.conf import settings;print(settings.RATELIMIT_ENABLE, settings.CACHES['default']['BACKEND'])"` | `True ...RedisCache` |
| Почта | Members → Invite → ваш второй email | письмо дошло; если нет — `docker compose logs app \| grep -i mail` |
| Медиа | загрузить картинку в Media Library, открыть её URL в приватном окне | картинка отдаётся без логина (так и должно быть, её скачивают соцсети) |

## 5. Бэкапы

```bash
mkdir -p /var/backups/brightbean
scripts/backup.sh /var/backups/brightbean          # первый запуск вручную
crontab -e
# добавить строку:
30 2 * * * cd /opt/brightbean-studio && scripts/backup.sh /var/backups/brightbean >> /var/log/brightbean-backup.log 2>&1
```
Бэкап содержит дамп базы, архив медиа и копию `.env`. Без `.env` (точнее, без `SECRET_KEY` и `ENCRYPTION_KEY_SALT`) токены соцсетей из дампа расшифровать нельзя. Копируйте каталог `/var/backups/brightbean` наружу (rclone в объектное хранилище, или `scp` на другую машину).

Проверка восстановления один раз: на чистом каталоге `git clone`, положить `env-STAMP` как `.env`, затем `scripts/restore.sh backups/db-STAMP.sql.gz backups/media-STAMP.tar.gz`.

## 6. Обновление

```bash
cd /opt/brightbean-studio
scripts/backup.sh /var/backups/brightbean
git pull origin main
docker compose up -d --build        # migrate выполнится автоматически
docker compose logs --tail=20 migrate
```

## 7. Типичные проблемы

- **Caddy не получает сертификат**: A-запись ещё не обновилась или порт 80 закрыт; `docker compose logs caddy`. Домен должен резолвиться в IP VPS с самого VPS: `dig +short ваш-домен`.
- **`migrate` падает с ошибкой аутентификации**: пароль в `DATABASE_URL` не совпадает с `POSTGRES_PASSWORD`. Если контейнер postgres уже создавался со старым паролем, нужно `docker compose down -v` (удалит данные!) или сменить пароль через `psql`.
- **Посты висят в scheduled**: воркер не запущен или нет повторяющихся задач (таблица выше). `docker compose logs worker`.
- **500 при первом подключении соцсети**: `ENCRYPTION_KEY_SALT` пустой или остался плейсхолдер.
- **Письма не уходят**: `EMAIL_HOST` пустой означает SMTP на localhost. Проверить лимиты: 6 писем в час на адрес, `EmailSuppression` в админке.
